# RSI 在 ALFWorld 上的四组配对消融

执行模型为 `deepseek-v4.1-flash`。两种写入器从空库处理同一批 12 条历史无记忆轨迹，每类任务 2 条。冻结两份技能库，对其余 122 个 valid_unseen 游戏各执行四组，每组每游戏一次。四组共用初始环境、执行提示和 30 步上限。全量组序列化全部有效条目，检索组查询最多 3 个簇、选最多 4 条技能，注入上限 512 token。每题打乱组别顺序并行执行。

## 建库

| 写入方式 | 调用 | 写入 token | 建库耗时（秒） | 生效／跳过／拒绝 | 最终有效条目 |
|---|---:|---:|---:|---|---:|
| curator | 24 | 28,601 | 33.8 | 12／0／0 | 12 |
| direct | 12 | 25,760 | 25.1 | 9／2／1 | 8 |

## 执行

| 组别 | 成功数 | 成功率 | 平均步数 | 单次注入 token 均值 | 每任务执行 token 均值 | 每任务执行 token 中位数 | 每成功一次总 token |
|---|---:|---:|---:|---:|---:|---:|---:|

| B 单次 Reflector，完整 Playbook | 110/122 | 90.2% | 11.58 | 1322 | 27,547 | 18,384 | 30,786 |

| D 单次 Reflector，两级检索 | 111/122 | 91.0% | 12.02 | 450 | 19,148 | 11,206 | 21,277 |

执行 token 使用服务商返回的全部 prompt 与 completion token，含已缓存输入，未折算账单。每成功一次总 token 为整组执行消耗加上该组一次建库消耗，再除以成功数，包含失败回合的成本。单次注入按 RSI 本地 tokenizer 估算，任务执行期间同一段记忆随提示重复发送。

## 逐题配对差异

| 从前组换到后组 | 由失败变成功 | 由成功变失败 | 成功率差（百分点） | 95% 区间（百分点） | 配对检验 p | 执行 token 变化 |

| A → D | 8 | 4 | +3.3 | [-2.5, +9.0] | 0.388 | -47.5% |

成功率差使用逐游戏配对 bootstrap 95% 区间（5,000 次），p 值使用双侧精确 McNemar 检验，未对多重比较校正。区间只覆盖游戏抽样差异。每种写入器建库一次，每组每题执行一次，跨建库批次与模型采样的变异尚待验证。该对照衡量完整 Playbook 与整体选择性读取策略的差异，其中包括两级检索、阈值和 token 上限。

未返回用量的执行请求数为 A 组 1 次，B 组 1 次，C 组 0 次，D 组 0 次。token 总量按可获取的 API 用量汇总。

## C、D 两组复测

复用首轮冻结的技能库、任务和提示词，对同一批 122 个游戏再各执行一次。下表的 token 为每任务执行均值。

| 配置 | 首轮完成数 | 复测完成数 | 首轮 token | 复测 token |
|---|---:|---:|---:|---:|
| C · Reflector + Curator，两级检索 | 111/122 | 116/122 | 18,931 | 17,704 |
| D · 单次 Reflector，两级检索 | 111/122 | 115/122 | 19,148 | 19,022 |

单次 Reflector 在建库阶段将调用次数减少 50%，写入 token 减少 9.9%。两轮合计，C 完成 227/244 个回合，D 完成 226/244 个回合。D 的平均执行 token 高 4.2%。少数长回复对均值影响较大；两轮均使用同一对冻结库。复测 D 组有一次请求未返回用量。
